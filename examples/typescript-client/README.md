# TypeScript API client (example)

A small, dependency-free client for the SAP AI Application Lab API, plus a
worked example of each of the seven calls a front end has to get right.

**This is a reference, not a package.** Copy `src/` into your app and change it.
It exists so that the envelope handling, the upload shape, the download filename
and the "we could not answer that" branch are all written down once, correctly,
rather than rediscovered per project.

---

## Files

| File | What it is |
| --- | --- |
| `src/types.ts` | The envelope and the cross-cutting types, hand-written so `data` narrows to non-null when `success` is true |
| `src/client.ts` | The client: one `request()` that unwraps the envelope, plus upload, download, paging and polling helpers |
| `src/examples.ts` | The seven operations end to end, and a `runFullJourney()` that performs all of them |
| `src/schema.ts` | *Generated.* Per-module payload types from the OpenAPI document (see below) |

---

## Run it

The API has to be running:

```bash
# in the repository root
uvicorn app.main:app --reload
```

Then:

```bash
cd examples/typescript-client
npm install
npm run typecheck        # no build needed to check it compiles
npm run demo             # runs the full journey against http://127.0.0.1:8000
```

`npm run demo` uses the bundled demo dataset, so it needs no file of your own.

Point it somewhere else with `API_BASE_URL=http://localhost:8080 npm run demo`.

## Generate the per-module types

`types.ts` covers what a generator cannot express. Everything else - the shape of
a finding, a forecast item, a blueprint section - comes from the API's own
OpenAPI document, so it cannot drift:

```bash
npm run generate:types
# = npx openapi-typescript ../../docs/openapi.json -o src/schema.ts
```

`docs/openapi.json` is committed and is regenerated by
`python scripts/generate_api_collection.py`, so a change to the API shows up as a
diff in code review rather than as a surprise in a front end.

Use them together:

```ts
import type { components } from './schema';
import SapAiLabClient from './client';

type Analysis = components['schemas']['AnalysisDetailSchema'];

const client = new SapAiLabClient();
const analysis = await client.get<Analysis>(`/po-risk/analyses/${id}`);
//    ^ fully typed, from the server's own schema
```

## The seven operations

```ts
import SapAiLabClient, { ApiError, saveToDisk } from './client';

const client = new SapAiLabClient({ baseUrl: 'http://127.0.0.1:8000' });

// 1. Health check
const health = await client.health();

// 2. File upload
const upload = await client.upload('/po-risk/upload', file);
// modules that take a form field:
await client.upload('/invoices/upload', file, { dataset: 'invoices' });

// 3. Start an analysis (synchronous today - this resolves when it is done)
const analysis = await client.analyze('/po-risk/analyze', {
  upload_id: upload.upload_id,
  generate_ai_summary: true,
});

// 4. Poll a status (a no-op today; the seam for when analyses go async)
await client.pollUntilComplete(
  () => client.get(`/po-risk/analyses/${analysis.analysis_id}`),
  { onProgress: (a) => setStatus(a.status) },
);

// 5. Retrieve findings (paged, filtered, stably ordered)
const page = await client.get(`/po-risk/analyses/${analysis.analysis_id}/findings`, {
  severity: ['critical', 'high'],
  limit: 25,
  offset: 0,
});
const everything = await client.listAll(
  `/po-risk/analyses/${analysis.analysis_id}/findings`, 'findings',
);

// 6. Download an export (the filename comes from the API)
const report = await client.downloadExport(
  `/po-risk/analyses/${analysis.analysis_id}/export`, 'xlsx',
);
saveToDisk(report);

// 7. Ask a copilot question
const reply = await client.askSupplierRiskCopilot({
  question: 'Why is supplier 0000390001 rated high risk?',
  supplier_id: '0000390001',
});
if (!reply.data_available) {
  show(`Not answerable from the loaded records: ${reply.unavailable_reason}`);
}
```

## Error handling

Every failure - network, timeout, non-JSON body, HTTP error, error envelope -
arrives as one `ApiError`:

```ts
try {
  await client.upload('/po-risk/upload', file);
} catch (error) {
  if (!(error instanceof ApiError)) throw error;

  if (error.isUserFixable) {
    // 400 / 422: the message is written to be shown.
    // "File type '.pdf' is not supported. Allowed types: .csv, .json, .xlsx"
    toast(error.message);
  } else if (error.isRetryable) {
    // 5xx, 429, or the API was unreachable.
    toast('Something went wrong. Please try again.');
  } else if (error.code === 'not_found') {
    router.push('/analyses');
  }

  // Always worth logging: it is in the server log too.
  console.error(error.code, error.requestId);
}
```

`error.message` is always safe to show a user - the API never puts a file path,
a stack trace or a provider payload in it. `error.requestId` is the value to
quote in a support request.

## Three things the UI must not skip

These are obligations, not suggestions. They are what keeps the product honest,
and they are easy to leave out of a first draft.

**1. Show where every number came from.** Every value carries an
`output_origin`. A figure a model wrote must not look like a figure the rules
computed:

```tsx
const ORIGIN_LABEL = {
  rule_based:   'Calculated',
  forecast:     'Forecast',
  ai_generated: 'AI-written',
  mock_ai:      'Mock AI',
  demo_data:    'Demo data',
} as const;
```

**2. Never present an estimate as a fact.** Every savings opportunity has
`is_estimate: true` and the response carries a `disclaimer`. Render it. "EUR
2.1m of savings" and "EUR 2.1m of modelled savings under the stated assumptions"
are different claims, and only one of them is true.

**3. Render the "cannot answer" branch.** The copilot and the contract Q&A both
tell you when the loaded data does not support an answer. Showing `answer`
regardless turns "I do not have that" into what reads like a considered
response.

And one standing caveat, on every page that shows a result: **no output has been
validated in a live SAP environment, and none of the data is real.**

## Authentication

There is none today. The client accepts a `token` (a string or a function, so it
can refresh) and sends `Authorization: Bearer …` when one is set; the API
currently ignores it. `GET /api/v1/auth-status` reports that honestly.

Wiring it now costs nothing and means the day authentication is switched on, the
front end changes in one place:

```ts
const client = new SapAiLabClient({
  baseUrl: process.env.NEXT_PUBLIC_API_URL,
  token: () => getAccessToken(),   // called per request
});
```

See [`docs/API_AUTHENTICATION_PLAN.md`](../../docs/API_AUTHENTICATION_PLAN.md).
